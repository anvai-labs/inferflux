This maintenance release carries the post-v0.5.2 deduplication refactors, the
ADR-0007 design record, and the ROCr spin-thread tamer (#267). Serving
defaults are unchanged; the only runtime behavior change is thread-scheduling
hygiene for ROCm builds.

## Scope and compatibility

- **ROCr thread tamer (#267, redesigned in #270):** on WSL2 (dxg path) with
  gfx1201, ROCm 7.x `libhsa-runtime64` leaves two `AsyncEventsLoop` threads
  spinning at 100% CPU each for the process lifetime (upstream fix
  rocm-systems#7898 unreleased; no `HSA_*` knob disables it; WSL2 does not
  enforce `SCHED_IDLE`/nice for service-cgroup threads). With the opt-in
  `INFERFLUX_ROCR_TAME=1`, `inferfluxd` confines these threads at creation:
  the server binary defines `pthread_create`
  (`server/rocr_pthread_interposer.cpp`), and every thread whose start
  routine lies in `libhsa-runtime64` is started through a trampoline that
  pins it to one shared core (bounding the cost to ≤1 core) and names it
  `rocr-hsa-N`. Priority is left alone (an inherited nice 19 could never be
  undone by threads ROCr starts later), and any non-ROCr thread a tamed thread
  starts gets the mask it would have inherited without the tamer. Identification is exact, so no other
  thread is ever confined; there are no signals, scans or background threads.
  The core comes from the server's affinity allotment (a valid
  `INFERFLUX_ROCR_TAME_CORE` inside it, else its highest CPU); a single-CPU
  allotment pins nothing. Counter
  `inferflux_runtime_spin_threads_confined_total` (documented in
  `docs/MONITORING.md`); decision logic in `runtime/rocr_spin_tamer.{h,cpp}`.
  Long-lived first-party threads now name themselves (`if-sched`,
  `if-http`, `if-decode`, …) for `top -H`, `/proc`, gdb and profilers.
  CPU-only, CUDA-only and non-Linux builds are unaffected.
- **Dedup rounds 1-6 (#259, #263 lines):** behavior-preserving
  deduplication (debug budgets, stale-lease release, factory assembly,
  lease-validation prologue, server start args, admin api-key mutation
  transaction). No config or wire-contract changes.
- **ADR-0007 (#264, docs only):** phased-execution design record for
  logprobs/structured output; no runtime change.
