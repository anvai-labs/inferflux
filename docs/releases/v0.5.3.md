This maintenance release carries the post-v0.5.2 deduplication refactors, the
ADR-0007 design record, and the ROCr spin-thread tamer (#267). Serving
defaults are unchanged; the only runtime behavior change is thread-scheduling
hygiene for ROCm builds.

## Scope and compatibility

- **ROCr spin tamer (#267, hardened in #270):** on WSL2 (dxg path) with
  gfx1201, ROCm 7.x `libhsa-runtime64` leaves two `AsyncEventsLoop` threads
  spinning at 100% CPU each for the process lifetime (upstream fix
  rocm-systems#7898 unreleased; no `HSA_*` knob disables it; WSL2 does not
  enforce `SCHED_IDLE`/nice for service-cgroup threads). In processes where
  `libhsa-runtime64` is loaded, `inferfluxd` starts a background worker that
  scans at startup, +10 s, +60 s, then every ~5 min (so models loaded at
  runtime are covered). Each scan identifies the pollers positively:
  threads that never block during a 1.2 s window (runnable ≥80% by
  `schedstat`, load-immune; ≤2 stime ticks; zero voluntary context switches;
  names ignored, since threads inherit their creator's name) are probed with
  a signal up to 3 times — only while running and not blocking/ignoring it —
  and only those with at least 2 sampled instruction pointers inside
  `libhsa-runtime64` are confined (nice 19 + `SCHED_IDLE` + co-pinning to one
  core), bounding the cost to ≤1 core. A busy third-party CPU threadpool or
  first-party thread can never be confined; a thread not proven backs off
  1→12 scans before re-probing. At most 8 live threads are confined at once.
  GPU sync latency is unaffected (verified under full CPU contention).
  `INFERFLUX_ROCR_TAME` (default on; `0` starts no thread) and
  `INFERFLUX_ROCR_TAME_CORE` (pin target); counter
  `inferflux_runtime_spin_threads_confined_total` (documented in
  `docs/MONITORING.md`); confined threads renamed `rocr-spin-N`. Long-lived
  first-party threads now name themselves (`if-sched`, `if-http`,
  `if-decode`, …), visible in `top -H`, `/proc`, gdb and profilers. CPU-only
  and CUDA-only builds start no tamer thread. The module lives at
  `runtime/rocr_spin_tamer.{h,cpp}`.
- **Dedup rounds 1-6 (#259, #263 lines):** behavior-preserving
  deduplication (debug budgets, stale-lease release, factory assembly,
  lease-validation prologue, server start args, admin api-key mutation
  transaction). No config or wire-contract changes.
- **ADR-0007 (#264, docs only):** phased-execution design record for
  logprobs/structured output; no runtime change.
