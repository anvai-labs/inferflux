This maintenance release carries the post-v0.5.2 deduplication refactors, the
ADR-0007 design record, and the ROCr spin-thread tamer (#267). Serving
defaults are unchanged; the only runtime behavior change is thread-scheduling
hygiene for ROCm builds.

## Scope and compatibility

- **ROCr spin tamer (#267):** on WSL2 (dxg path) with gfx1201, ROCm 7.x
  `libhsa-runtime64` leaves two unnamed `AsyncEventsLoop` threads spinning at
  100% CPU each for the process lifetime (upstream fix rocm-systems#7898
  unreleased; no `HSA_*` knob disables it; WSL2 does not enforce
  `SCHED_IDLE`/nice for service-cgroup threads). `inferfluxd` now samples
  `/proc/self/task` over a 1.2 s window after models load and confines
  pure-spin threads (≥80% utime, ≤2 stime ticks, zero voluntary context
  switches, unnamed comm, cap 4) with nice 19 + `SCHED_IDLE` + co-pinning to
  one core, bounding the cost to ≤1 core. GPU sync latency is unaffected
  (verified under full CPU contention). New env knobs `INFERFLUX_ROCR_TAME`
  (default on) and `INFERFLUX_ROCR_TAME_CORE`; new counter
  `inferflux_runtime_spin_threads_confined_total`; confined threads renamed
  `rocr-spin-N` for `top -H` visibility. CPU-only and CUDA-only builds are
  unaffected (no spin threads exist to find; the tamer is a no-op).
- **Dedup rounds 1-6 (#259, #263 lines):** behavior-preserving
  deduplication (debug budgets, stale-lease release, factory assembly,
  lease-validation prologue, server start args, admin api-key mutation
  transaction). No config or wire-contract changes.
- **ADR-0007 (#264, docs only):** phased-execution design record for
  logprobs/structured output; no runtime change.
