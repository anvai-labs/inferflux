This maintenance release carries the post-v0.5.1 scheduler-accounting and
gate-stability follow-ups from
[#243](https://github.com/anvai-labs/inferflux/issues/243). Runtime behavior
changes are limited to batch admission accounting; serving defaults are
unchanged.

## Scope and compatibility

- `EstimateQueueTokenCost` charges prefill-queue items carrying `logprobs` or
  `response_format` their prompt plus decode budget (they execute the whole
  budget inside the admitted executor pass since v0.5.1's stateless-Generate
  fix), so `max_batch_tokens` no longer over-packs concurrent stateless decode
  work (#248). Skipped requests are selected alone on the next batch; no
  starvation. With `decode_burst_tokens=0` and no timeslicing, plain-traffic
  batch composition is unchanged.
- The `[memory_contract]` dequant recovery contract re-measures up to three
  times so a co-resident process's transient allocation no longer fails the
  gate spuriously (#250; the exact-2 MiB co-tenancy flake from the v0.5.1
  promotion). Genuine retained-buffer regressions still fail every attempt —
  verified with an injected leak on the real card. Test-only change; case
  counts unchanged.
