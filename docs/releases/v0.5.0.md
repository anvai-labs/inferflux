This minor release combines the additive dual-listener TLS configuration from
[PR #235](https://github.com/anvai-labs/inferflux/pull/235) with completion and
embedding wire-contract repairs from
[PR #234](https://github.com/anvai-labs/inferflux/pull/234). CMake remains the
package-version authority; the v0.4.0 tag and published assets remain immutable.

## Scope and compatibility

- One server can retain its plain loopback listener and expose a separate TLS
  listener using the same routes and authorization. Existing single-listener
  configuration remains supported. See [configuration](../CONFIG_REFERENCE.md).
- `/v1/completions` retains legacy text response shapes through buffered and SSE
  content, finish, logprob and terminal-usage frames. Legacy reasoning text stays
  intact for single, multiple-choice and best-of results. Chat continues to
  separate reasoning and extract tools; chat-only tools are rejected on the
  legacy route.
- `/v1/embeddings` honors float/default and base64 encoding. Base64 encodes
  little-endian IEEE754 float32; invalid formats fail before backend dispatch.
  See [API contracts](../API_SURFACE.md). No embedding dimension reduction or
  completion prompt-array support is added.
- Trusted GPU CI uses an isolated test-port range instead of ports now occupied
  by identity services. This changes test infrastructure, not serving ports,
  authentication, rate policy or gateway deadlines.

Follow the [release process](../ReleaseProcess.md). A workflow's overall success
does not count skipped package or GPU jobs as evidence. Standard Linux release
archives are CPU-only; this deployment needs a separately recorded mixed-GPU
build from the exact published source. Do not downgrade a dual-GPU deployment by
installing the generic CPU archive.

## Deployment and recovery

Capture the existing service unit, binary and loaded libraries, configuration and
rollback hashes before authorized downtime. Stop through the service manager,
then verify the owned process and GPU allocations have exited before exclusive
trusted-main GPU gates. Do not run pull-request code on the persistent GPU runner.

Preserve credentials, model files, persisted policy/cache and all failed evidence.
Stopping a process resets its volatile cache; it is not a cache-purge operation.
Stage the accepted mixed-GPU bundle under an immutable source-qualified directory,
verify its library resolution, and update only the owned service launch settings.
Restore the captured service on failed acceptance, then verify readiness and
identity separately from launch success. Keep existing rollback routes intact.

Use the current bounded gateway deadlines; timeouts fail acceptance. Explicitly
zero reported cache tokens do not prove zero executed cache reuse. Readiness,
wire conformance and accounting joins do not establish origin cancellation,
durable agent continuation or full formation quality.
