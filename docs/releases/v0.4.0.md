# InferFlux v0.4.0 release candidate

**Status: In progress — version preparation, not publication or deployment.**

This candidate adds opt-in endpoint request admission from
[PR #229](https://github.com/anvai-labs/inferflux/pull/229), merged at
`01bee958829a679e10e5033c1d29abe91b085795`, to the released v0.3.0 baseline
`276e199918414b2e701bf1636d3bbecf1e107e56`. CMake is the package-version authority.
The new minor version identifies an additive configuration/API feature; the existing
v0.3.0 tag and assets remain immutable.

## Scope and compatibility

One listener can enforce separate startup `auth.endpoint_limits.generation` and
`auth.endpoint_limits.embeddings` buckets while retaining the positive shared
per-subject ceiling. Admission checks and debits shared/class balances atomically.
Effective policy provenance and endpoint rejection scope/retry information are visible.
Without endpoint configuration, legacy behavior and rejection responses stay unchanged.
See [configuration](../CONFIG_REFERENCE.md) and [operator rollout](../AdminGuide.md).

Persisted shared policy takes precedence over environment/YAML. The inspected v0.3.0
service's 120 requests/minute limit overrides YAML 600; endpoint buckets alone cannot
increase that shared ceiling. Rate and burst are not concurrency or measured GPU capacity.
Eight embedding requests/s is an acceptance target to measure with fixed input/batch
sizes and competing generation, not a release performance claim. Runtime admin mutation
changes only the shared limit; endpoint classes are startup configuration.

Sandhi source at `cd676a3` has no `/v1/embeddings` ingress or provider transport.
Embedding acceptance remains direct to InferFlux until a separate gateway contract
lands. Gateway generation tests cannot substitute for embedding accounting evidence.
Keep authenticated origin access when the gateway is optional.

## Deployment and rollback

Promote and verify the published release before replacing the shared port-8080 service.
Use one effective shared policy and optional per-class buckets; record source/binary
hashes, configuration provenance, 429 scope/retry behavior and fixed-workload results.
Keep the gateway's confirmed buffered deadline; its timeouts remain acceptance failures.

For rollback, restore the known prior binary and its exact prior configuration and
policy state. Remove new endpoint configuration when using an older binary that does
not enforce it; verify the old shared limit rather than silently assuming per-endpoint
protection. Do not clear shared cache or overwrite immutable release artifacts. Fix
published defects forward under a new version. This preparation does not close C5/#184,
prove 8 requests/s capacity, add Sandhi embeddings or fix the separate side-effect-free
`--version` CLI gap recorded in Victor G66.
