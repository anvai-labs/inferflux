This maintenance release carries dedup round 7 (PRs #285–#293), the
unload-error/eviction-counter hardening (#284), and the validation-window
records (#290, #294). **No intended behavior change**: every device-side
consolidation shipped with SASS comparison and rig A/B evidence at or under
the bench host's contention floor, and the CPU suite stayed at 668 cases /
4,402 assertions throughout.

## Scope and compatibility

- **Dedup round 7** (`docs/planning/DEDUP_ROUND7_LEDGER.md` holds the full
  per-PR evidence table): the packed dp4a dispatch tables and the per-quant
  mmvq kernel families were consolidated behind shared catalogs, bodies, and
  tail policies — kernel entry names, template parameter lists, and
  signatures unchanged (dispatch tables and by-name test launches compile
  untouched). The norm-quant Q8_1 phases became shared
  `ComputeRmsFromWarpSums`/`QuantQ8_1DualBlocks` helpers in
  `quant_common.cuh`; the FA host GQA ladders became `DispatchGqaRatio`
  (function-pointer form — nvcc parses function-template names as
  expressions in template-template argument position); the err-checked
  ensure-norm lambdas became `LlamaForwardTyped` members. t150 duplication:
  75 → ~53 clones; `.jscpd.json` committed as the regression baseline at
  minTokens 50.
- **Unload honesty (#284, issue #283):** `DELETE /v1/admin/models` answers
  409 `model_in_use` with the live reference count when the model exists
  but is held, reserving 404 for unknown ids;
  `ModelRouter::ModelReferenceCount` is the advisory probe.
- **Eviction-decision counters (#284):** the slot-pressure admission
  outcome is observable without the env-gated decision log.
- **Records:** ADR-0008 (serialized KV tier; implementation data-gated on
  a <50% accepted-reuse trigger that the closed validation window measured
  at 100%), the round-7 ledger, and the 2026-10-18 resolution doc's closing
  addendum.
