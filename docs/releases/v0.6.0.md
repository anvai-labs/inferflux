## Scope and compatibility

- **KV bystander-eviction fix (#276):** `RadixPrefixCache::EvictOneSequence`
  reports the retired sequence id, `Scheduler::AllocSeqSlot` collects them,
  and `ProcessBatch` discards a prefix candidate only when the matched donor
  itself was retired (diagnostic stages split into
  `capacity_eviction_donor` / `capacity_eviction_bystander`). Previously ANY
  slot eviction during admission dropped the request's own candidate even
  though `Lookup` had just LRU-protected the matched donor — on slot-constrained
  backends this turned nearly every repeat request into a full re-prefill
  (live probe signature: `cached_tokens 0, 0, 432` for three identical
  requests; post-fix `432, 432, 432` with TTFT halved). Frozen acceptance
  contract updated in the same change; the historical `capacity_eviction`
  stage stays whitelisted so pre-split evidence bundles still project.
- **llama.cpp v0.7.0 (#277):** submodule moved from v0.2.0 (`bb4caa7`, Aug 21)
  to v0.7.0 (`620d222`, Oct 15). `external/nlohmann` synced to llama.cpp's
  vendored 3.12.0 amalgamation as an InferFlux-owned pin (one tree-wide json
  version is required; the pin is not consumed from the submodule's `vendor/`
  layout so first-party includes do not depend on submodule churn).
  `structured_output_adapter` parses the already-validated schema text into
  `common_json` (request-side validation and error strings unchanged). CMake
  compiles four additional llama.cpp common sources
  (json/json-schema/trie/unicode). Unlocks Qwen3.5/Qwen3.8-class
  architectures for llama-family backends.
- **Patched ROCr runtime scripting (#271):** `scripts/rocm/build_patched_rocr.sh`
  builds the backported `libhsa-runtime64` (rocm-7.2.0 tag, sha-pinned) and
  stages it together with AMD's prebuilt WSL thunk `librocdxg` v1.2.2 and the
  `PATCHED_ROCR.json` completion marker; deploy remains the documented manual
  copy into the release's `runtime/bin`.
- **Records and hygiene (#273–#275):** git hooks marked executable in the
  index, v0.5.3 publication record, self-hosted runner lifecycle documented
  as a systemd unit with the GPU PATH.

Serving defaults are unchanged. Operators on slot-constrained backends should
expect materially higher accepted KV reuse on repeat traffic; no wire-contract
or config changes.
